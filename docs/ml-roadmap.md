# 机器学习模型规划（用户愿景记录 + 可行性分析）

> 记录日期：2026-08-22。这是用户提出的长期 ML 愿景，分四层。按"对交易盈利的贡献 / 数据可得性 / 工程成本"排序推进，不要求一次建成。

## 用户提出的四层模型

### 1. 战队统计样本层（赛季/版本演化学习）
- 特征：各战队近期地图 ban/pick 率、不同地图手枪局胜率等
- 要求：**随时间更新**--赛季更替、游戏版本更新（如大行动/竞技修改弹）会改变特征分布，模型需适应概念漂移（concept drift）
- 可行性：★★★★★ 数据可得（bo3.gg 历史库 + HLTV），随版本打标签（demo 的游戏版本/时间戳天然分组）
- 模型方向：Glicko-2（分地图、随时间衰减）作基础评分；梯度提升树（XGBoost/LightGBM）做聚合预测；用滑动窗口重训练 + 按版本分组的特征漂移监控。参考 haidamykyta/cs2（XGBoost+Glicko-2+校准+Kelly）

### 2. 回合决策层（序列依赖）
- 问题：某回合胜利后，下一回合及更远期双方会做什么（经济决策、buy/force/eco、momentum 连胜效应）
- 可行性：★★★☆☆ 需要**回合级数据**，来源是 GOTV demo 解析（demoparser2/awpy：每回合胜负、双方经济、装备价值、存活情况）。历史 demo 可从 HLTV demo 下载器批量获取；仅覆盖有 demo 的比赛（顶级赛事基本全覆盖）
- 模型方向：序列模型（Transformer encoder / GRU）以回合为步长，输入回合状态（经济、比分、上一回合结果），输出下一回合各队胜率 + buy 类型概率。中期目标。CS 经济系统的规则性强（连败补助、强制局），这部分可以先写**规则引擎**再让 ML 学残差
- 对应策略：赛中实时交易（Phase 3）--只有做 live 才需要回合级预测

### 3. 阵型/指挥策略层（2D 走位学习）
- 问题：从 demo 转换的 2D 视图学习队伍走位/阵型调度、单回合进程预测
- 可行性：★★☆☆☆ 数据存在于 demo（每 tick 的玩家位置、视角、击杀事件），awpy 可解析成 2D 坐标轨迹；但这是**研究级工程**：数据量巨大（一场比赛 ~10 万+ tick）、需要 GPU 训练、学术界也是开放问题（类似 deep learning for sports tactics）
- 模型方向：轨迹预测（类似车辆轨迹的 sequence-to-sequence / 图神经网络 GNN，节点=选手，边=队友关系），或先降维成"阵型聚类 + 关键节点统计"（如 A 点 5 人 rush 频率、默认控图习惯）这种**可解释特征**喂给第 1 层
- 建议：远期。先用特征工程版（阵型统计指标）而非端到端轨迹学习
- 用户的半职业视角在这里价值最大：知道什么战术信号重要（默认站位、翻盘局习惯、暂停后变化），可以指导特征设计

### 4. 选手个人表现层（个人近期状态）
- 特征：个人 Rating 波动、近期状态（上升/下滑趋势）、换阵/新阵容磨合度、不同角色（IGL/AWPer/明星哥）权重
- 可行性：★★★★☆ HLTV/bo3.gg 有逐场个人数据；"状态"需要自己定义指标（如 EWMA of Rating、相对队伍基线的偏离）
- 模型方向：时间序列平滑（EWMA/Bayesian form 模型）+ 个人 Rating 对队伍胜率的边际贡献（可从第 1 层模型的特征重要性学出）
- 注意：阵容变动信息（转会/暂替）需新闻源，Liquipedia 转会表 + 用户主观输入

## 分层依赖与推进顺序

```
第1层(统计样本) + 第4层(个人状态)  ->  比赛级胜率预测   -> 赛前价值下注(Phase 1-2)【优先】
第2层(回合序列)                    ->  盘中胜率预测     -> 赛中实时交易(Phase 3)
第3层(2D阵型)                      ->  战术理解/特征增强 -> 远期增强，非独立盈利来源
```

**核心判断**：交易盈利主要来自第 1+4 层（比赛级预测），应最先建；第 2 层服务于赛中交易；第 3 层是长期增强。所有层共享同一数据底座（demo 解析 + 自建历史库）。

## 技术底座（各层共用）

- **Demo 解析**：`demoparser2`（Python，快）或 `awpy`（含地图坐标/可视化）；HLTV demo 下载器（ReagentX/HLTVDemoDownloader）
- **特征存储**：SQLite/Parquet 分层表（match -> map -> round -> tick 采样）
- **训练框架**：LightGBM/XGBoost（1、4 层）-> PyTorch（2、3 层）
- **漂移管理**：按游戏版本/赛季打标签；定期重训 + 校准曲线监控（预测概率 vs 实际频率）；版本大更新后缩短回看窗口
- **标注校准**：一切概率输出过 isotonic/Platt 校准后才进 Kelly 仓位计算
