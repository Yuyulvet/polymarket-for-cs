# 新版赛中数据重建与 Map Winner 粒度对照

这是离线研究流程，不接入 HLTV、盘口、工作台模型或实盘。旧缓存保持不动。

## 数据重建

`cs2ml.inplay_rebuild` 为每张 demo 保存独立分片、结构化审计和排除原因。
先用 `--demo` 多次指定一组普通、加时、重复加时与已知异常地图进行 pilot，
再重建具有现有 clean chronology 的完整候选集合：

```powershell
.venv\Scripts\python.exe -B -m cs2ml.inplay_rebuild --history-only --workers 2 --output-dir data/map1/rebuild/<new-run>
```

`--history-only` 的意义是优先重建能进行严格时间验证的候选地图，不是全部本地 demo。
未选中的路径及理由记录在 manifest；没有时间元数据的 demo 不凭文件名猜测日期。
去掉此开关可以解析全部本地 demo，但无时间记录的结果不能进入前向模型对照。

每个新目录包含：

- `manifest.json`：输入文件大小/修改时间、代码与历史表 SHA-256、解析器版本及选择规则。
  demo 本体只记录大小/修改时间变化保护，**不声称对数百 GB 的 demo 全部做了内容哈希**。
- `shards/<index>/audit.json`：每张地图的事件、身份、完整结果与历史交叉核对情况。
- `progress.jsonl`：逐图完成情况和耗时；失败不静默丢失。
- 合并的 `inround_events.parquet`、`round_states.parquet`、`midround_v2.parquet` 和 `map_labels.parquet`。
- `audit.json`：完成后生成的覆盖、排除原因和产物行数汇总。

没有相应有效数据时不生成空的 parquet 产物。缺失初始化/身份、边界歧义或不完整地图必须显式记录。
`midround_v2` 是稀疏 30 秒状态，不用于反推最终比分。
Map Winner 标签独立来自原始完整回合胜者、每回合实际 CT/T 阵容和 MR12/MR3 规则；
旧 history 只提供时间代理与交叉核对，不用于补漏。新旧结果冲突会隔离，不能进入正式候选样本。

### 中断与恢复

显式指定相同 `--output-dir --resume`、相同输入集合及选择参数。
代码、解析器、历史表或输入指纹变化时拒绝恢复；已完成分片校验产物 SHA-256 后才复用。
存在半写分片或半完成合并时保留供审查，不自动覆盖或删除；改用新目录处理。
已完成的 run 不重写。并行最多两个 worker，以控制解析峰值内存。

## 第一轮模型对照

`cs2ml.inplay_map_research` 使用新解析的完整地图标签，在完全相同的有效事件状态上预测稳定队伍 A 赢图：

1. 比分、阵营、地图、当前回合与已过时间。
2. 同上，再加入本回合开始装备。
3. 同上，再加入当前人数、HP 与炸弹状态。

这是固定的小型诊断对照，第一版**没有赛前实力先验、市场概率或位置/道具特征**。
不把“击败比分基线”写成“击败市场”，也不把回合胜率作为地图胜率。
多个事件嵌套在回合、地图与系列赛内，样本数不能当成独立比赛数量。
训练只用在测试时间块之前结果已可用的系列赛；同系列地图不跨训练/测试，
缩放与拟合仅使用训练数据。所有候选共享样本和时点，不按不同模型结果挑样本。

历史时间仍是系列赛结果可用时间代理，demo tick 不等于实际 live 接收时间。
已查看的历史结果只能作为诊断；最终验收需要冻结方案后的新时间区间和同期可成交盘口。
