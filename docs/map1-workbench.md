# Map 1 本地纸面工作台

## 阶段边界

本版本用于开发验收和前向研究，不是实盘交易机器人。
没有钱包、私钥、授权和下单接口；页面中的现金、成交和盈亏均为模拟。
用户已确认：[先完成开发和验证，再单独考虑实盘](map1-development-plan.md)。

## 启动与日常操作

在项目根目录运行：

```powershell
# 首次使用才需要准备历史数据；已有 data/map1 产物时无需重复生成。
.venv\Scripts\python.exe -B -m cs2ml.map1 prepare

# 运行工作台；只监听本机，不对局域网或公网开放。
.venv\Scripts\python.exe -B -m cs2ml.map1_web --port 8765
```

浏览器打开 `http://127.0.0.1:8765`。

1. 点击「刷新公开赛程」。程序从官方 sports 元数据取得 CS2 分类，按最新事件分页查询。
   默认最多 10 页、每页 100 项；页面上限触发时会记录截断警告，不声称覆盖全部赛事。
2. 选择未来 72 小时内符合条件的比赛。没有严格匹配的 Map 1 市场、已开赛、已结束、
   不支持的市场或不接受订单的市场会排除。勾选「显示已过期 / 排除」可查看原因。
3. 在「从 HLTV 导入」粘贴 `https://www.hltv.org/matches/比赛编号/比赛名称`，点击读取公开比赛页。
   系统提取本场地图顺序与名单，保存本次页面文本、SHA-256、解析结果和实际接收时间。
   地图 TBA、非赛前、队名不一致、开赛时间相差超过 5 分钟或名单不完整时不能确认。
   五分钟仅是跨源赛程容差；仍需人工检查赛事、双方和具体场次，不能以同队名替代比赛身份。
4. 首次遇到选手时核实 HLTV ID 与 SteamID64 的关系；可选择本地历史候选并填写身份依据，分批保存。
   候选来自 demo 数据，**仅昵称相同不会自动确认为同一人**。已核实的稳定 ID 映射在本研究数据库中复用。
   十名选手身份全部核实、证据有效后，勾选比赛复核并确认。确认时重新读取市场、严格绑定 token。
   系统仍以本次确认时间为最早可用时刻，不用 HLTV 的比赛日期或较早手工时间回填预测。
   若无法自动读取，展开「人工核实备用入口」，亲自核实来源后录入地图、五人名单和时间；
   该入口会明确记录为人工声明，不冒充自动验证。
5. 点击「启动纸面采集」。名义调度间隔 3 秒，比赛发现每 5 分钟、结算检查每分钟。
   实际速度取决于请求延迟和比赛数量；上一轮没有完成时不重叠启动下一轮。
   只对开赛前 60 分钟内已确认的比赛采集。没有确认，不生成预测或交易。
6. 「暂停采集」停止后续轮次，已发出的只读请求可能完成当前轮。
   也可使用「采集一轮」「检查结算」做有界操作。关闭终端或 Ctrl+C 退出服务。
7. 页面查看纸面账本和运行异常，下载完整报告、原始快照与结算证据。

### HLTV 证据更新与限制

- 只接受固定 HLTV 域名的 HTTPS 比赛链接；不接受其他地址、查询参数、端口、凭据或重定向。
  每次读取有超时、体积与结构上限，不使用登录凭据，不尝试绕过访问限制。
- 采集启动后，仅复查已人工确认且处于赛前 60 分钟窗口的 HLTV 场次，目标每场 5 分钟一次；
  每轮最多一个请求，全局至少间隔 15 秒，实际间隔受延迟和比赛数量影响。暂停时不后台读取。
- 证据超过 15 分钟不再有效；读取失败或解析不完整时暂停该来源的自动重试，需人工重新导入。
  最新失败证据会覆盖“当前可用状态”，但不会删除历史成功证据，不能偷偷回退到旧页继续产生信号。
- 每轮采集会比较最新地图、HLTV 比赛/队伍 ID、赛程与已确认的十人身份。
  变更立即阻止下一次预测/纸面成交，但轮询不能保证变更发生时立即知道，也不能证明名单永不变动。
  同一内容刷新只更新证据引用，不回写原确认。首次快照后需改变确认内容时使用新的研究批次。
- HLTV 的开赛时刻取页面 epoch 毫秒，不解析浏览器本地显示时间；选手只取本场 lineups，不取队伍常规阵容。
- 队名只做保守的大小写/标点规范化，不模糊合并 Academy/Junior 或自动猜测品牌别名。
  比如 HLTV 短名与市场完整品牌不同会被阻止；当前需人工核实备用入口，后续再做带证据的队名别名管理。
- 「HLTV 原始证据」导出含原始页面文本及解析记录；哈希针对所存页面文本的 UTF-8 编码，不是网络压缩字节。
  页面不在本地以 HTML 执行。选手身份映射冲突不允许静默覆盖；部分成功也不会掩盖批次冲突。

工作台重新启动后**始终暂停**；历史记录保留，不会自动恢复网络采集。
服务运行时需要电脑保持唤醒，不安装系统服务、计划任务或开机启动项。

## 存储与不可回写的记录

- 默认数据库：`data/map1/desk.sqlite`，SQLite WAL 模式。运行中备份应使用 SQLite 备份功能；
  最简单是退出服务后复制数据库，不要只拷贝仍在写入的主文件而忽略 WAL。
- 赛事原始元数据、首次发现与最后更新时间会保存；不符合条件的事件也保留原因。
- 地图/名单确认被审计；首次观测后不能再修改该事件的上下文。需要修正研究方案时新建研究批次，
  不覆盖或删除旧证据。
- 快照包括完整双边深度、费用、延迟、模型特征、训练时间和失败原因。
  同事件同接收时间完全一致的重复记录去重，内容冲突则报错。
- 原始观测与结算重建纸面账本；重启、重复结果查询不会重复计入收益。
- 模型输入文件、相关代码哈希和纸面参数被固定。已有确认/观测后发生变化，拒绝沿用数据库：

```powershell
.venv\Scripts\python.exe -B -m cs2ml.map1_web --db data/map1/desk-next-cohort.sqlite --port 8765
```

仅有赛程、还没有任何人工确认和观测的空研究批次允许更新协议。
不要把多个协议的结果混在一起挑选最好的参数；新方案用新的前向样本验证。

## 成交、成本和结算

固定实验参数：虚拟初始现金 1000、每笔 10 股、每股扣费后优势门槛 0.05，
客户端延迟假设 0.5 秒，另加市场当前 `secondsDelay`。
这些是研究参数，不是仓位建议，也不表示模型概率可靠。

入场按真实卖盘深度和限价检查，不按中间价成交。延迟后必须再收到符合条件的订单簿；
簿时间早于允许成交时刻、价格越过限价、深度不足、参数变化、信息失效都会阻止成交。
断线后超过成交窗口仍没有新簿，待成交模拟订单到期，不会无限等待后补成交。
每场最多一次成功纸面入场；未结算仓位显示成本，不伪造文件末尾平仓。

自动结算要求：

- Gamma 的对应 Map 1 已关闭且 `umaResolutionStatus == resolved`。
- CLOB 的同一 condition 已关闭，两个 token 身份完全一致。
- 两个明确的布尔 `winner` 字段中恰好一个为真。

只使用明确胜者生成二元兑付，不读取 0/1 末价推断赛果。记录的是**本地首次观察到已确认结果的时间**，
并保存两份原始响应。平分、未知、冲突或接口失败都保持未结算，并在页面提示待核验。
GUI 当前不自动结算 50–50，也没有人工覆盖结算入口；原 CLI `replay` 可使用明确来源的双 token 兑付记录独立研究。

## 页面与安全

界面显示虚拟余额、已实现盈亏、持仓成本、观察场次、二元评估样本、模型/市场概率指标和拒绝原因。
组合模型仅在有足够的过去已结算样本后评估；无样本时显示「待积累」，不显示虚假成绩。

服务固定绑定 `127.0.0.1`；校验 Host、同源 Origin、每次启动随机 CSRF token 和请求长度。
人工备用入口的来源文字只作本地记录，不由服务抓取；HLTV 专用入口只访问严格白名单比赛地址。
市场、HLTV 和用户文本通过 `textContent` 显示，避免作为 HTML 执行。
未实现任何交易路由。不要通过反向代理把这个本地研究工具暴露到公网。

## 验收命令

```powershell
# 离线逻辑 + 临时 SQLite + 本机 HTTP 测试，不调用外部 API。
.venv\Scripts\python.exe -B -m unittest discover -s tests -v

# 明确允许只读公开 API 的冒烟测试；不保存成前向预测或交易样本。
.venv\Scripts\python.exe -B -m scripts.smoke_map1_desk --live
```

页面验收覆盖初始暂停、公开赛程加载、选择比赛、确认表单、没有确认时不采集、异常状态、启动/暂停及布局。
自动化测试另外覆盖未来信息、错误身份、延迟后旧簿、重启恢复、协议变更、重复/冲突结果、跨站请求和完整纸面结算闭环。

## 仍需验证的内容

- HLTV 页面可自动提取，但首次身份关联及具体场次仍由人工复核；选择哪些比赛也会产生样本选择偏差。
  目前不全站爬取、不自动找 HLTV 比赛、不以名字猜队伍或选手身份，也不保证页面可访问性。
- 当前历史样本有限，旧数据可用时刻仍是结果结束后的代理假设，模型尚未证明优势。
- HTTP 轮询不是低延迟行情系统；不能证明实盘一定获得显示的深度或成交。
- 长期、大规模数据需进一步做增量账本和存储优化；当前复盘从原始数据重放。
- 费用以美元等值模拟，未实现真实账户扣费份额、成交回报、余额或授权对账。
- 本轮工程验收不包含长期前向收益、回撤/成本压力的统计检验，更不意味着通过实盘门槛。
