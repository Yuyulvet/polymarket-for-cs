# Polymarket CS2 交易策略分析报表

> 基于 2026-08-22 官方文档调研 + 生产 API 实测（详见 `polymarket-api-research.md`）。
> 决策背景：Python 技术栈、新账户（signature_type=3）、先模拟盘、操盘者本人为 CS2 半职业选手。

## 一、Polymarket 玩法速览（CS2 视角）

### 1. 基本盘
- Polymarket 是运行在 Polygon 链上的预测市场。每个市场是一个二元问题，有 Yes/No 两种代币，**价格 = 隐含概率**（$0.52 的 Yes ≈ 市场认为 52% 概率）。
- CS2 市场实测：锦标赛冠军盘是 **negRisk 事件组**（如 EWC 2026 CS2 Winner = 29 个"X 战队夺冠"子市场，恰好一个结算为 Yes）。通过 tag `cs2`（id=100677）可拉到全部。
- 交易在 CLOB（中央限价订单簿）撮合，链上结算。**没有 AMM**，流动性全靠做市商挂单。
- 比赛结束走 UMA 预言机结算（无争议约 2 小时），获胜代币赎回 $1/枚。**不需要盯盘结算，也不需要"平仓"——也可以中途卖掉离场。**

### 2. 对策略有决定性影响的五条规则

| 规则 | 内容 | 策略含义 |
|---|---|---|
| **费用不对称** | Taker 费 = 股数 × 0.05 × p × (1−p)（50¢ 时最高 ≈ 每股 1.25¢）；**Maker 完全免费 + 返佣 15%** | 吃单很贵，挂单被奖励。市价追价策略必须把费算进 edge |
| **开赛清簿** | 体育市场开赛时刻自动撤销所有未成交限价单 | 赛前挂单不会"意外"带进比赛；做市策略必须处理开赛事件 |
| **赛中撮合延迟** | 比赛进行中，可成交订单需等待 `secondsDelay` 窗口后才撮合，**延迟期间不可撤销** | 赛中"看到事件→抢跑"的执行确定性打折，专业做市商同样受限，但对吃单型策略是核心摩擦 |
| **negRisk 转换** | 组内任一市场的 1 股 No 可原子转换为其他每个市场各 1 股 Yes | 提供了组内定价锚（Σ Yes ≈ $1）和免费的重构库存手段 |
| **价格精度分层** | tick_size（0.01~0.0001）动态变化、min_order_size（常见 5 股） | 下单引擎必须自动适配，否则静默被拒 |

### 3. 你的优势定位

半职业选手的知识（地图池相性、队伍近期状态、换阵/教练变动、比赛动机、线上赛 vs LAN 差异、选手个人状态）正是预测市场最难被公开数据捕捉的部分——**你的 edge 来自信息，不来自速度**。策略选择应围绕这一点。

## 二、四个方向逐一分析

### 方向 A：赛前价值下注（Pre-match Value Betting）

**原理**：赛前用自己的 CS2 判断 + HLTV/排名数据构建胜率估计 p̂，与市场价格 p 比较。当 `p̂ − p > 阈值 + 费用` 时买入错价一侧，持有到结算或价格回归后卖出。

- **盈利来源**：市场定价错误（散户情绪、战队名气偏差、小战队信息不被定价）。
- **优势**
  - 与你的核心优势（游戏理解）完全对齐
  - 无延迟、无清簿问题，基础设施最简单（Gamma 轮询即可，连 WebSocket 都不是必需）
  - 可以用 **maker 限价单**入场 → 零费用 + 返佣，等于多出约 1~2% 的 edge
  - 价格回归后可提前卖出，不必等结算，资金周转可控
- **劣势**
  - 机会频率取决于赛事日历（大赛期间密集，平时稀疏）
  - 需要概率模型**校准**（不是"谁赢"而是"赢的概率是多少"）——这需要模拟盘积累记录来验证
  - CS2 市场流动性可能偏薄，大额建仓会推动价格（需实测盘口深度）
  - 资金有时间占用成本（不过有 4% 年化持仓奖励作缓冲）
- **所需基础设施**：Gamma API 市场扫描 → HLTV/排名数据管道 → 概率模型 → 模拟盘信号记录（不需要下单功能即可启动）
- **适配度：★★★★★ 起步首选**

### 方向 B：赛中实时交易（Live Trading）

**原理**：比赛事件（关键回合、上半场比分、经济局崩盘、map score 变化）实时改变真实胜率，若市场反应慢，抢先进出。

- **盈利来源**：信息速度差 + 波动。
- **优势**
  - 波动大、机会密度最高
  - 你对回合内 momentum（经济系统、暂停时机、心态崩盘）的理解远超一般参与者——这是最深的 edge
- **劣势**
  - **撮合延迟直接打折扣**：看到事件后下的单要等延迟窗口才撮合，价格可能已经动了；且延迟期间不可撤单
  - taker 费高（高频进出累计显著）
  - 需要可靠的**实时回合级数据源**（官方 sports WS 对 CS2 的覆盖粒度待验证，可能要自接直播数据）
  - 对手是专业做市团队（他们同样受延迟约束，但有更好的基础设施）
- **所需基础设施**：回合级实时数据 + CLOB market WS + 低延迟下单 + 风控熔断——是四个方向中工程量最大的
- **适配度：★★★☆☆ 第二阶段，信息优势最大但摩擦也最大**

### 方向 C：做市（Market Making）

**原理**：围绕估计的公允价双边挂单，赚取 spread + maker 返佣（15%）+ 4% 持仓年化，用偏移报价管理库存风险。

- **盈利来源**：价差 + 返佣 + 流动性奖励。
- **优势**
  - 零 taker 费，返佣和奖励是**正和**收入（不依赖对手犯错）
  - CS2 市场流动性薄 → spread 宽，理论做市空间大
  - 与价值判断天然结合：认为 Yes 应值 55¢ 就把报价中心放 55¢，等别人来错价成交——**这本质上是"被动版价值交易"**
- **劣势**
  - **逆向选择**：你挂的单被吃，往往因为对手（可能是你这样的行家）知道得更多——做市是把自己的信息劣势变现成 spread 的生意，与你"信息强"的定位部分矛盾
  - 需要持续在线报价、库存对冲（negRisk 转换/merge 可用但复杂）、tick 变更处理、开赛清簿应对
  - 薄流动性市场单笔利润小，需要长期挂机运行
- **所需基础设施**：market WS 增量订单簿维护 + 自动改价循环 + 库存管理——中等偏上工程量
- **适配度：★★★★☆ 高级形态："信息驱动的做市"（报价向自己判断倾斜）是 A+C 的合体，长期最优**

### 方向 D：套利（Arbitrage）

**原理**（三类）：
1. **negRisk 组内套利**：Σ(所有结果 Yes ask) < $1 时买全组，锁定无风险利润；Σ(bid) > $1 时反向
2. **双边套利**：某市场 Yes bid + No bid > $1（双边都卖）；或 Yes ask + No ask < $1（买齐后 merge 赎回 $1）
3. **跨平台套利**：与传统博彩公司/其他预测市场赔率对比错价

- **盈利来源**：定价不一致，理论无风险。
- **优势**
  - 无需观点，无信息劣势
  - negRisk 转换和 merge 提供了链上原子的执行工具
- **劣势**
  - 机会已被专业机器人 7×24 盯守，持续期以秒计，剩余利润薄
  - 多腿执行有滑点风险（一腿成交一腿飞）
  - 跨平台套利涉及出入金摩擦，实际上接近价值交易
- **所需基础设施**：多市场实时价格监控 + 快速原子执行
- **适配度：★★☆☆☆ 不做主策略，作为**监控模块**常驻（发现了就吃，不依赖它吃饭）**

## 三、方向对比总表

| 维度 | A 赛前价值 | B 赛中实时 | C 做市 | D 套利 |
|---|---|---|---|---|
| 盈利来源 | 定价错误 | 速度+波动 | 价差+返佣 | 定价不一致 |
| 与"游戏理解"优势契合 | ★★★★★ | ★★★★☆ | ★★★☆☆ | ★ |
| 工程复杂度 | 低 | **最高** | 中高 | 中 |
| 受撮合延迟影响 | 无 | **大** | 中 | 中 |
| 受 taker 费影响 | 可用 maker 规避 | 大 | 无（maker 免费） | 中 |
| 机会频率 | 低~中 | 高 | 持续 | 稀疏 |
| 理论风险 | 模型错误风险 | 执行+费+模型 | 逆向选择+库存 | 滑点（近无风险） |
| 启动顺序 | **第 1** | 第 3 | 第 2~3 | 常驻监控 |

## 四、推荐路线图

**Phase 1 —— 模拟盘 + 数据管道（现在开始）**
1. Gamma API 扫描 CS2 市场（tag 100677），记录盘口快照与价格历史
2. HLTV/排名数据管道（调研进行中）
3. 概率模型 v1：Elo/排名基线 + 你的主观调整系数
4. 模拟盘引擎：信号 → 记录"如果下单会怎样"（用 maker 价成交假设 + 计入费用）→ 统计校准曲线（预测 60% 的事件是否真以 ~60% 频率发生）
5. 套利监控模块常驻（副产品）

**Phase 2 —— 实盘小资金（模拟盘曲线校准后）**
- 只做方向 A，单笔 ≤ 资金 2%（Kelly 折半起步），单日亏损上限熔断
- 用 maker 限价单入场，错价消失即撤
- 你的账户为 signature_type=3（Deposit Wallet），SDK 自动处理，但需先小额验证一笔

**Phase 3 —— 升级形态**
- 信息驱动做市（A+C 合体）：长期在 CS2 市场双边报价，中心价向自己的模型倾斜
- 赛中交易（B）：前提是验证回合级数据源可靠 + 实测算子延迟真实影响

## 五、风控原则（写进代码，不靠自觉）

1. 单笔风险 ≤ 账户 2%；单市场敞口 ≤ 10%；单日亏损 5% 熔断停机
2. 模拟盘 → 实盘切换必须显式配置，实盘初期硬编码资金上限
3. 下单前校验：tick 对齐、min_order_size、盘口深度（大单拆分）
4. 心跳保单机制（10s 无心跳自动全撤）作为崩溃安全网启用
5. 所有实盘操作留审计日志（信号、盘口快照、订单、成交）
6. 私钥与 API 凭据只放 `.env`/环境变量，永不入库入 git
