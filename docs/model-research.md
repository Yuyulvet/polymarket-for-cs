# Map 1 模型审计与粒度对照

本轮顺序：先统一标签、时间和可预测资格，再对照模型，最后用新增时间段验收。
昵称/身份管理不再是研究主线；离线模型使用 demo SteamID，不要求用户逐人确认 HLTV 名单。
此流程不改变工作台的身份保护，也不会自动部署研究候选。

## 运行

```powershell
.venv\Scripts\python.exe -B -m cs2ml.map1_research
```

默认读取 `data/map1/history.parquet`、`features.parquet` 和 `data/player_features.parquet`。
结果写入全新的 `data/map1/research/<UTC时间戳>/`：`report.json` 和逐场 `predictions.parquet`。
可用 `--output` 指定一个不存在的目录；拒绝覆盖旧实验，不更新工作台数据库或模型。

## 首先检查什么

- 每张图和系列赛/地图序号唯一；Map 1 目标与清洗历史的双方、地图、标签、时间完全一致。
- 完整终局比分符合 MR12/MR3，胜负标签与比分一致。这里只是内部一致性，不冒充独立赛果核验。
- 用现有干净历史重建 16 个旧基线特征，与缓存逐列比较；不一致时停止，不悄悄使用陈旧特征。
- 历史结果必须在预测前可用，同一系列赛排除；缓存可用时间仍是整场结束加延迟代理，不是实际收到时间。
- 在线和离线共用双方完整阵容历史各至少 3 图的门槛，分别报告全体共同预测样本和符合历史覆盖门槛的共同样本。
  “符合历史覆盖门槛”不代表 veto、实时名单、盘口、费用、结算等交易条件均满足。

## 固定对照，不自动选最好成绩

当前固定比较六个候选：恒定 50%、历史阵容 Elo、现有 16 特征模型、去掉旧伤害字段的 14 特征模型、
12 个选手特征模型、14 个阵容特征加 12 个选手特征模型。

Elo 固定 K=20、尺度 400，从当时已知的历史地图结果更新；同一可用时刻的结果一起更新，避免行顺序影响。
逻辑回归沿用固定 C=0.25、无截距和对称训练，镜像样本只在时间划分之后产生。
没有网格调参、按末段成绩挑选赢家或自动替换工作台模型。

选手特征按 SteamID 携带历史，不因换一位队员就丢掉其余四人的记录。包括跨图/当前图的历史胜率、
log K/D、首杀/首死、补枪和爆头率；本场五人等权汇总，低样本向预先固定的先验收缩。
使用严格过去的干净地图关联；重复选手-地图、身份不符、回合数不符、计数异常会排除并报告。
未知选手和每位选手历史数量显式展示，不静默删除稀疏目标样本。

旧 `player_features.py` 把护甲伤害加进 damage/ADR，且部分原始事件语义尚未独立审计。
因此保留 16 特征模型只用于复现；新选手模型和去伤害候选不使用这个字段。
去掉字段并不等于已经修好所有原始特征，仍需后续按真实 demo 验证计数语义。

## 如何读结果

- 每个分区在相同预测场次比较 Brier、Log loss、校准分组、AUC、命中率以及样本覆盖。
- Brier/Log loss 越低越好；校准组要同时看样本数。一次猜对不证明概率可靠。
- 逐场配对 Brier 差值为“候选减参考”；负值只是该组样本上较好，不等于统计显著或未来有效。
- 原先已看过的末段统一命名 `diagnostic_tail`：系数在边界前冻结，但它已不是全新未见测试集。
  历史状态允许随已发生且已可用的结果更新，与赛前历史特征一样；这是预先固定的更新规则。
- 所有候选最终仍需要协议冻结后的新增时间区间验证。多候选筛选、同队伍/同赛事/同日相关性都必须考虑。
- 本轮不计算执行盈亏，没有把新增特征的离线概率改进等同于超过市场，更没有证明实盘净期望为正。

## 之后才进入赛中粒度实验

按赛前先验、回合比分/阵营、回合开始经济、局内人数/HP/炸弹、位置/道具逐层增加信息。
在同一批未来地图、同一批可预测时点上做消融。每层先证明概率增量，再对比同期市场与执行成本。
事件行再多，也不是同样数量的独立比赛。详见 [赛中验证契约](live-validation-contract.md)。
