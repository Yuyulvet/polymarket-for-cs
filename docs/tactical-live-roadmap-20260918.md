# 战术建模与直播小地图：优先级清单

记录日期：2026-09-18。状态：已开始地图坐标与高清证据采集开发；识别、战术特征及新模型对照尚未完成。

目标：先验证可用的局势描述，再公平比较基础模型、XGBoost 和小型空间—时间神经网络，最后验证真实直播信息下的概率增量与纸面交易表现。更换算法、增加信息、改进采集必须分别归因。

本文件补充现有研究计划，不替代 Map 1 身份绑定、严格时间验证和交易安全约定。当前不接钱包、不授权、不发真钱订单。此前粗站位实验没有证明稳定增量，但不能否定尚未建模的战术关系。

## P0：先验证直播小地图能提供什么

- [x] 检查已有录像截图，并开始 StarLadder 固定直播布局的 Cache 连续片段试采。
- [x] 建立 Cache、Mirage、Dust2、Inferno、Ancient、Nuke、Anubis 七图版本化坐标元数据目录。当前仅元数据；导航、遮挡和地图版本匹配仍待验证。
- [ ] 片段应包含正常展开、多人标记重叠、交火、回防、回放或界面切换；优先寻找有同场 demo 的录像。
- [ ] 确认小地图是否持续显示双方位置、图标和编号是否可辨、是否旋转或缩放、是否有隐藏位置和明显卡顿。
- [ ] 建立裁剪、地图校准、队伍标记识别、区域归属和短轨迹原型；先做区域人数和移动趋势，不要求一开始完美恢复十名选手身份。
- [ ] 输出观测时间、位置或区域、身份置信度、缺失标记和最后观测时间；不得把插值或跟踪预测标成真实观测。
- [ ] 人工核对一批帧，记录区域人数准确性、位置误差、身份交换、丢失时长、有效覆盖率与处理延迟；分开统计重叠和正常状态。

验收：交付可回看的识别叠加样例与错误清单，明确可靠/不可靠字段。量化门槛在训练与调参前按目标用途约定；原型成功不等于支持实盘。界面切换、旧帧、回放和严重遮挡必须拒绝或降级输出。

直播可行性是实用路线的早期检查，不阻止独立开展离线数据工作。若视觉精度不足，缩小到区域级信号；历史完整信息研究仍可继续，但不得称为实时可用。

## P1：统一历史与视觉数据接口，冻结评估协议

- [ ] 放开满员、满血、未下包限制，保留有效非终局状态；正确处理下包后存活条件、换边、加时和完整地图身份。
- [ ] 固定时间采样并保存短历史窗口，不根据之后的交火挑选“交火前样本”；确保所有输入时间不晚于预测时点。
- [ ] 基础字段包含人数、HP、装备、比分、时间、炸弹状态与拆包相关条件；逐人字段保存位置、朝向、可靠道具状态及轨迹。
- [ ] 区分完整 demo 真值、视觉观测、估计值和未知值；记录数据来源、可用性、时效与地图版本。
- [ ] 冻结同一系列赛分组的时间前向切分、样本权重、训练内调参方案和主要评价指标；已被查看的历史仅作探索，新时间区间留作最终验收。
- [ ] 记录当前回合和最终地图两个目标，分别评分；不得把回合胜率直接当成地图胜率。

验收：所有候选共用预测时点和测试比赛；通过标签、身份、时间泄漏和缺失处理测试。密集帧数不当作独立比赛数量。

## P2：实现三组战术特征并核验语义

- [ ] 局部参战人数：结合地图可达路径，估计短时间内能加入区域交战的双方人数及其血量、装备。
- [ ] 支援与补枪条件：预计到达时间、交火区域覆盖、路径或视线是否受阻；不能以直线距离直接等同补枪能力。
- [ ] 移动趋势：过去几秒的集结、推进、撤退、区域人数变化、多路接近同步性。
- [ ] 检查地图导航、坐标、朝向和道具数据是否足以支持计算；近似量必须明确标记，不捏造准确支援时间或可见性。
- [ ] 抽取进攻、反清、回防、多人拥挤等片段，将特征叠加到回放，人工检查它是否描述了真实局势。
- [ ] 场景划分只使用当时的信息；未来的接触区域、移动或伤亡只能做目标，不作为当前特征。

验收：可展示具体样例及失败样例，解释每个特征的输入、单位、近似条件和缺失行为。无需人为规定某种战术必定提高胜率。

## P3：建立三类候选并做公平对照

- [ ] 保留现有基础模型作为参照；记录真实算法和参数，不将所有提升树统称为 XGBoost。
- [ ] XGBoost：基础信息版与加入战术特征版；依赖与硬件需求先检查，参数在训练期内部选择。
- [ ] 小型空间—时间神经网络：学习逐名选手的历史状态与关系；设置同信息量对照，不把额外轨迹输入带来的提升全部归给网络。
- [ ] 可选近时目标：短时接触、区域进入、伤亡或下包；包含无事件状态，谨慎处理回合提前结束的样本。辅助目标是否改善主要目标必须单独检验。
- [ ] 神经网络多随机种子重复训练并报告分布；不只展示最好的一次。
- [ ] 报告 Brier、Log loss、校准、分阶段和分场景结果、概率更新速度及推理延迟；不只看方向准确率。
- [ ] 以系列赛为单位评价不确定性，记录多候选选择与重复研究局限；若互有优势，融合也须在训练内完成并独立检验。

验收：可复现的对照报告，清楚区分算法增量和信息增量。没有增量就保留简单模型，不自动部署胜出的历史候选。

## P4：检验视觉误差与真实到达延迟下是否仍有效

- [ ] 在相同样本上，分别用 demo 真值和真实视觉识别结果驱动同一个模型。
- [ ] 训练或压力测试中加入合理的位置抖动、漏检、身份不确定和延迟；模拟不能替代真实录像测试。
- [ ] 对齐视频帧时间、接收时间、处理完成时间、盘口接收时间与可执行时间；未知的真实比赛发生时间不得伪造。
- [ ] 比较完整信息、直播可用信息与同期市场参照；分清预测优势和到达时间优势。
- [ ] 对缺帧、陈旧状态、源间不同步和低置信度设置拒绝或退回基础模型的规则。

验收：用真实直播可获得的信息，在新比赛上检验增量；离线完整位置有效但视觉输入无效，不算实时路线通过。

## P5：冻结策略后做前向纸面验证

- [ ] 区分持有到地图结算与短时买卖波段两个目标，分别设计入场、退出、持仓时限和风险约束。
- [ ] 计入实际可买/可卖价格、深度、延迟、费用、未成交与特殊结算；不能用中间价冒充成交。
- [ ] 策略在训练/开发阶段选择，之后冻结，用新时间区间报告净收益、回撤、场次分布和不确定性。
- [ ] 纸面结果不自动解锁真钱；真实交易另行取得用户明确授权并进行执行和风险验收。

## 当前第一轮工作范围

1. 使用单一 StarLadder HUD 做采集原型；通用坐标接口覆盖七图，本场从 Cache 校验，不限定 Inferno。
2. 已实现高清小地图裁剪、参考完整帧保存、仿射校准及独立检查点校验工具。实际直播地标标定和玩家标记识别仍待完成。
3. 做人工可检查的叠加回放，列出真实可获得的字段和错误类型。
4. 据此确定统一数据接口和第一批战术特征；开始搭建共用评估入口。

第一轮目标是确认数据路线，而非承诺当天下午完成全部模型训练。支持七图的元数据不等于七图识别均已通过；暂不扩展多赛事 HUD 或启动大规模调参和云 GPU 付费任务。

用户已要求立即开发并提供本场两端链接，因此开展限时、限量、只读试采。没有设置自动唤醒，没有自动交易。具体运行记录见 `radar-pilot-20260918.md`。
